# 阅讯：两分钟演示

入口：https://signal-desk-demo.onrender.com/ 。先登录并提前让免费实例启动；不要在视频中展示密码、邀请码或控制台密钥。若没有合格近期新闻，演示真实空状态和来源诊断，不用旧闻代替。

| 时间 | 操作 | 要讲清楚 |
| --- | --- | --- |
| 0:00–0:20 | 选择绿龙，展开来源状态，查看新闻与比赛两栏 | 战队实体映射；Dust2自动RSS、Tavily按需搜索、PandaScore比赛分别处理 |
| 0:20–0:40 | 选择战队采访，打开一篇原文 | 时间和内容类型过滤；读到新闻标题不等于已读全文 |
| 0:40–1:00 | 点击外语卡片“译成中文”，展开原文 | 只翻译标题/短摘录；缓存、预算及失败保留原文 |
| 1:00–1:20 | 少看这类→仅这条→撤销 | 持久化反馈事件、可解释范围；不要说一次隐藏已经证明推荐效果 |
| 1:20–1:45 | 模型问答：“总结绿龙近期采访，列出依据” | 库存检索→证据取回→有来源回答；无证据时应承认不足 |
| 1:45–2:00 | 打开运行记录，展开本次模型调用并导出JSON | 工具、耗时、token与费用可追溯；成功不代表事实准确 |

## 如何回答“装个Skill不就行了吗”

Skill能描述如何查消息和总结。这个项目还要持续采集、为不同用户保存关注与反馈、控制共享缓存和额度、将来源失败与个人隐藏分别解释，并通过Web提供阅读与撤销入口。模型负责受限的工具选择和组织回答，身份、日期、来源和预算由服务端执行。

## 录完后保存什么

视频或截图；部署提交号；演示日期；实际问题与回答摘录；run_id；对应原文链接；实际不成功的一步。运行JSON不包含回答全文，因此事实评估还需要单独记录回答与证据。私人导出保留在本地，不把账号信息放进仓库。
