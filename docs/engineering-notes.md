# 工程设计与面试说明

更新：2026-10-09。依据当前代码、公开部署、用户提供的真实轨迹与首轮兴趣评估。实现、部署、场景验收分开记录。

## 为什么值得做，而不是装一个 Skill

Skill可以教Agent查资料；本项目提供多用户Web入口、持续采集与持久化库存、跨会话关注和反馈、可解释撤销、身份限制与预算。Skill也可以调用这个服务。价值来自可运行的业务闭环，而不是提示词本身。

已实现并真实运行受限模型工具循环。模型负责选择工具和总结；采集、过滤、记忆重放、身份与费用控制由后端执行。不是多Agent、自主研究或向量RAG系统。

## 什么叫做好了（Eval）

| 层面 | 判断标准 | 当前证据 |
| --- | --- | --- |
| 供给 | 原文日期/对象/类型可核对，返回→过滤→入库→展示可以解释 | [原文审计](eval/news-supply-audit-20261009.md)已开始；具体线上召回待补 |
| 推荐 | 用户独立兴趣标签，反馈与留出分离，对照排序并保留未知 | 1人30篇历史数据首轮回放；新规则、多用户效果未确认 |
| 模型问答 | 事实有证据、引用对应、工具选择合理，无证据不编造 | 一个真实费用/工具轨迹；10–20例实际问答评估待补 |
| 产品和运维 | 非开发者完成关注→搜索→阅读→反馈→撤销；身份与恢复场景验收 | 公网部署与首位朋友反馈；完整多人流程、恢复验收待补 |

首轮留出前五明确想看由1条变3条，反馈后有1条未知，精确P@5为N/A、界限60%–80%。不是统计置信区间或线上准确率。历史18项模拟模型检查不代表真实模型能力，也不是最新修改的全量结论。

## 场景规则与上下文工程

股票使用六位代码；绿龙映射Team Spirit，供应商赛事名称可能为Spirit。先按对象、30天窗口与新闻/比赛类型过滤，再处理有界候选，避免全局500条截断挤掉目标对象。

模型不拥有任意联网能力：`search_items`查询库存，`get_evidence`取短证据，可选`search_news`对一个已关注公开对象补搜。工具通过nanobot ToolRegistry注册，参数Schema限制字段、长度与枚举；用户身份由后端绑定。检索最多5条，证据摘要最多500字。

默认最多3轮、可补搜时4轮，工具总数最多6次，输出800 tokens，请求序列化上限16KB，问答超时40秒。系统提示将问题、关注名称和工具内容视为不可信数据；模型最终返回回答及证据ID，后端校验并重建引用URL。这些是工程限制，尚未进行上下文策略对照实验。

## 记忆系统

PostgreSQL保存关注、阅读状态和反馈事件。撤销记录undone_at并保留历史，排序重放有效事件。偏好按用户和关注对象隔离，可按内容类型、来源或只隐藏本条；无法分类时不扩大类型学习。旧对象级反馈兼容保留，权重限幅，重复反馈隐藏同事件键。

最近500条是候选上限，不是记忆寿命；窗口外关联反馈仍参与计算。没有向量记忆、自动画像训练或时间衰减。事件键通常由URL生成，不能声称已解决跨平台同事件归并。标题分类也不等于核验全文。

## 可靠性与成本

- URL唯一键幂等入库；来源客户端有超时与响应大小上限，失败保留库存。`/health`检查进程、`/ready`检查数据库；免费实例休眠会暂停周期采集。
- 搜索使用数据库缓存、30秒租约与原子额度预留；成功缓存6小时、零结果15分钟、失败5分钟。固定basic一次请求预留1 credit，没有自动重试。
- 模型预算先原子预留，成功按token与配置报价结算。默认月¥50、日¥3、单次上限¥0.5；预留金额不是实际消耗。
- 搜索另设日/月及每用户额度。项目¥200/月为预算目标，尚未与完整月账单对账。
- 一个真实模型样例估算¥0.01785，不能当平均调用成本。失败/不确定请求的保守计费与回退需结合轨迹解释。

## 安全与观测

后端身份限定工具、列表与证据范围；模型不能设置user_id。密钥仅在服务端，搜索只发送规范化公开对象；允许名单校验HTTPS域名，拒绝任意目的地，采集不跟随重定向。没有Shell或写文件工具。

密码使用scrypt，令牌签名，管理接口独立token，公开注册有邀请码。登录令牌保存在localStorage；密码找回、令牌撤销、登录限流和完整双账号/提示注入验收尚未完成。不能称通过安全审计。

AgentRun记录run_id、工具参数、耗时、结果数、错误与费用；不记录原始问题、密码或完整反馈历史。列表诊断区分候选、质量/类型过滤、反馈隐藏和最终展示。公开来源汇总不能证明某篇文章在某用户列表可见。

## 可聊的失败案例

1. PandaScore全局分页不包含目标战队：改为先解析战队ID再请求，并展示返回、可展示、丢弃和分页上限。
2. API标识被拼成“原文”导致404：取消伪链接，明确展示“供应商记录，无原文网页”。验收要检查引用目的地，而不是只看入库成功。
3. 采访方向返回综合新闻：搜索入库、工具返回、列表筛选统一内容类型；不以综合新闻填补采访。标题分类仍可能误判。
4. 收录非零但个人列表为空：范围内统计明确两条候选均被反馈隐藏，显示相关反馈和撤销入口；不自动重置用户偏好。
5. 搜索仍漏新闻：先核查原文存在与发布日期，再区分供应商召回、日期/实体过滤和个人隐藏；不能连续放宽规则让卡片“看起来更多”。
