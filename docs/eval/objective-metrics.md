# 阅讯：可复核的项目指标与面试呈现

更新：2026-10-15。本文区分已观测事实、设计约束与待测目标。数字不能天然证明真实性；哈希也只能检测文件变化，不能证明原始记录真实。可信度来自公开方法、完整分母、保留失败、外部来源/账单交叉核对和现场复现。

## 最值得收集的指标

| 指标 | 固定口径 | 证据及边界 |
| --- | --- | --- |
| 固定来源捕获率 | 指定来源、对象和7天窗口内，成功入库的应收事件 / 来源可核对的应收事件 | 以官方发布清单或独立人工整理的清单为分母，先冻结筛选规则；不能声称是全网召回率。转载按事件去重 |
| 收录时延 P50/P95 | 首次入库时间 - 来源发布时间 | 分来源报告；历史补录单列，缺失/估算日期单列。6小时轮询不是秒级实时；冷启动和调度延后都保留 |
| 正文可用率 | 在固定抽样文章中，正文成功且确为文章内容的篇数 / 所有尝试篇数 | HTTP 200和字数够多不足以证明正文正确；提供原文链接、抽样方法、人工复核。拒绝访问也计入失败 |
| 引用可解析率 / 证据支持率 | 前者为合法引用 / 所有引用；后者为原文支持的关键主张 / 所有可核对主张 | 引用格式自动校验；内容支持关系仍需独立复核，不能把格式通过率写成准确率 |
| 问答技术完成率、P50/P95 | 完整窗口内成功终态请求 / 全部终态请求；统计服务端起止耗时 | 无证据返回单列；失败和回退不删除。服务端耗时不等于用户端等待时间；冷/热启动分别统计 |
| 资源消耗 | 每请求token、搜索credit、MCP调用次数、估算费用分布 | 账单对账才称实际成本；缺失usage不当0元，缓存命中单列。数据API调用数不是人民币费用 |
| 可靠性与隔离 | 重复采集新增重复记录数；越权测试实际泄露数 / 预先定义用例数 | 可现场重放固定用例；用例全部通过不等于线上绝对安全，更不等于问答正确 |

用户价值还可以记录：独立试用人数、重复使用天数、精选阅读/反馈比例、完成指定资讯任务所需时间。必须排除开发者账号，先说明统计窗口和有效用户定义。5位愿意试用不等于5位活跃用户。P@K是个人偏好评价，不能包装成客观事实正确率。

## 本次可复算的历史观测

输入为用户于2026-10-09导出的 `signal-runs-2026-10-09 (1).json`，scope 为 `own_latest_50_runs`，实际23条不同运行记录。不是连续一周全站记录，也不是本次新版的验收结果。

其中12次 `model_agent`：

- 技术执行成功10次、失败2次，分母12。
- 服务端终态耗时：P50 4,834ms，P95 7,776ms。使用 nearest-rank；样本12时P95实际就是最大值，不能作稳定性能承诺。
- 按当时配置报价估算：12次合计¥0.159042；P50 ¥0.013432。不是账单实际扣款，也不包含搜索、服务器或数据API成本。
- 记录到的失败为缺少行内引用1次、JSON解析失败1次。
- 这些记录不能给出“答案正确率”“全站可用性”“次日留存率”。

复算脚本只读文件，不调用任何收费服务，不输出问题正文或账号信息：

```bash
.venv/bin/python scripts/eval/operational_report.py \
  --input '/path/to/signal-runs.json' \
  --output data/eval/operational-report.json
```

输出含输入SHA256、去重后的运行ID、分任务统计、缺失字段计数和局限。原始文件及生成报告默认不提交；对外展示前单独脱敏。重复记录按ID去重，冲突快照拒绝处理。

## 下一轮7天评估（方案，不是已完成结果）

1. 先提交协议及commit：固定关注对象、渠道、时段、样本选择规则；不要观察结果后挑最好看的来源。
2. 每天独立保存来源发布清单、调度记录、入库时间及失败原因，空消息日、额度耗尽和停机也保留。
3. 采集比较使用同一来源候选快照：旧的全量时间流 vs 新版精选/历史补录/聚合。报告阅读卡片减少数，同时人工核对有无遗漏独立事件和更新。
4. 问答固定任务集覆盖有证据、缺证据、时间过滤、错误对象、越权请求；比较只检索和模型取证模式。冻结问题、输入证据和版本，成本与质量同时报告。
5. 推荐质量由至少一位未参与开发的人复核；展示逐条原始标注，分歧保留。小样本报分子/分母，避免只报漂亮百分比。
6. 将聚合报告、统计脚本、版本号、部署记录、脱敏失败案例放README；金额与提供商账单核对。未获得允许不发布他人阅读历史或付费全文。

## 简历怎么写

指标不是入场券。一个真实可访问、能解释约束和失败恢复的完整项目，比不可信的“准确率95%”更有价值。

现阶段可写（实现事实，不暗示评估完成）：

> 独立开发并部署多用户资讯Agent，接入RSS、搜索及金十MCP，完成实体匹配、幂等入库、账号隔离与证据问答；设计按用户反馈调整的采集计划、有限工具循环和事务化预算控制，记录工具调用、token、耗时及失败回退原因。

本轮功能上线后可补：

> 针对新来源历史数据挤占未读的问题，分离历史补录与日常消息，构建跨关注的每日精选；对可明确识别的宏观数据事件聚合展示，保留逐篇证据与后续更新。

模型最多4轮、工具最多6次、每日调用额度等属于**工程约束**，可以写清楚，但不要称作测得的性能提升。已有单用户兴趣标注可作为探索性实验，不能概括为所有用户都提高。
