# 首周运行观察：2026-10-16 至 2026-10-22

## 冻结口径

- 时间范围：北京时间2026-10-16 00:00（含）至2026-10-23 00:00（不含）。这是观察计划，不是已完成一周的结果。
- 统计对象：无用户归属的固定来源采集轮次；不读取账号、个人问答、阅读或兴趣反馈。
- 部署版本：新采集轮次记录Render提供的Git SHA；旧轮次缺少版本时标为unknown，不归功于新版。快照的deployed_commit仅代表抓取快照时版本。
- 执行结果：success、partial、failure、running分开统计。来源级缓存跳过、无订阅、未配置、额度耗尽及unknown也分别保留。
- 成功执行不等于来源覆盖完整。正文已缓存数不等于正文正确率。
- 首次入库延迟仅对RSS/API已知发布时间计算，缺失时间、未来时间、超过24小时补录和搜索估算日期分别记录。24小时内首次导入仍可能进入样本，因此不称为稳定采集延迟。

## 自动保存

复用既有GitHub Actions `Prepare daily news`，不增加采集频率或外部数据工具调用。每轮现有采集后读取受SYNC_TRIGGER_TOKEN保护的 `/api/admin/sync/observation?days=7`。

Actions中下载名为 `collection-evidence-<run-id>-<attempt>` 的Artifact；保留30天。内容仅含白名单统计字段，不上传collection.json原始响应、密钥、账号、文章正文、问题、个人关注或反馈。

采集步骤最多20分钟，整个job最多25分钟，给归档留下时间。采集失败时仍尝试只读归档；如果实例不可达，记录抓取失败类型/HTTP状态。整个job被取消、runner不可用或达到job总超时仍可能没有Artifact；不能只看有Artifact的成功任务，需同时核对Actions任务列表。

快照回看最近7天，最多2000轮采集与5000条入库元数据，超过上限明确标记。重叠的库存统计不能相加；汇总脚本只按运行ID去重汇总轮次，库存快照留作单次核对。

## 本地复算

将不同Actions任务的JSON下载到不同目录，避免同名覆盖：

```bash
.venv/bin/python scripts/eval/collection_report.py \
  --input data/eval/observation-week/*/collection-observation.json \
  --start '2026-10-16T00:00:00+08:00' \
  --end '2026-10-23T00:00:00+08:00' \
  --output data/eval/observation-week/report.json
```

输出有输入哈希、抓取失败、去重后轮次数、各状态分母、来源计数、版本分布、耗时P50/P95及没有观测记录的日期。尚未来到的日期也不抹除；window_has_ended为false时不能写成完整一周成果。

## 这一周仍需要补的证据

1. 捕获率：独立保存官方/媒体应收事件清单，冻结对象和相关性规则，用其作为分母；不能拿当前库存当全网分母。
2. 问答质量：固定有证据、无证据、时间筛选、对象混淆与越权问题；保留回答、引用、失败和人工判定。已有个人运行导出工具可供复算，不公开他人内容。
3. 产品效果：同一候选快照比较时间流与精选，复核聚合是否漏掉独立事件或修正；旧标注不能代表新版用户效果。
4. 费用：外部账单与调用记录对账；24次/天MCP上限是调用约束，不是已验证的费用金额。

静态检查与历史数据分析可以立即完成；上述真实质量结果和完整7天观察不得提前填写。下一次汇总应连同失败和缺失记录发布。
