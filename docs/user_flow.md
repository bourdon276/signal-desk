# 小项目 0：首版用户流程

本文件保留完整产品流程。2026-10-07 一周 MVP 仅实现[当前计划](../PLAN.md)中的关注、阅读、反馈、撤销与证据检索；个人数据删除入口、复杂原因分类和长期推送属于后续阶段。

## 1. 开始使用

用户注册/登录后选择股票、伦敦金宏观资讯或游戏；每个关注项属于该用户。默认不把开发者的两个股票和三个游戏加给所有人。页面显示各关注项当前可用来源、更新时间和覆盖缺口。

## 2. 阅读信息流

卡片至少展示标题、事件时间或“未知”、来源名、官方/社区类别、原文链接、推荐原因。多来源报道同一事件时合为一组，能展开查看各来源。官方公告优先标识，社区讨论不得显示成已证实事实。用户可按领域过滤和查看最近一次成功更新；采集故障会显示状态。

## 3. 反馈与记忆

每张卡片提供“感兴趣”“没兴趣”“重复”“不喜欢这个来源”。“没兴趣”需选择原因：当前子主题无关、已经知道、暂时不想看；不把单次负反馈直接解释为永远不关注某股票或游戏。“重复”屏蔽同一事件；“来源不喜欢”只下调该来源；主题反馈仅作用于该用户和相应主题。每次反馈可查看与撤销，画像由反馈事件重算。

## 4. 摘要与追问

仅在来源允许且证据充分时生成摘要；逐条给原文依据。用户问“今天通鼎互联有什么消息”时，检索对应代码的已入库信息，并说明时间范围、来源故障和未覆盖源。资料不足时答“目前可用来源未发现”，不说“没有消息”。不提供自动交易动作或买卖建议。

## 5. 外部试用与退出

邀请用户通过 HTTPS 登录，完成关注、浏览、反馈和撤销。用户可删除个人关注、阅读/反馈记录；删除后不再参与个性化。试用数据只收集实现功能和 Eval 必需的匿名化指标，公开截图或访谈引述需逐项同意。

## 首版验收场景

| 场景 | 期望结果 |
| --- | --- |
| 用户 A 点“不喜欢这个来源” | 只影响 A 的该来源排序，不改变 B 或其他来源 |
| 用户 A 标记“重复” | 同一事件不再推给 A，其他事件不受影响 |
| 来源断更 | 显示最后成功时间，卡片不伪造新内容 |
| 官方公告与社区帖子同题 | 官方/社区标签清楚，内容聚合但证据不混淆 |
| 摘要缺少依据 | 不输出确定性事实，保留原文链接或说明未知 |
