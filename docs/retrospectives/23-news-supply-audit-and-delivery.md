# 复盘23：先核查供给，再统一交付事实

日期：2026-10-09。

## 做了什么

- 人工查阅出版社、赛事主办方与公司披露原文，整理绿龙与通鼎互联7个样例：4个近期正例、3个过期对照。
- 保存供给审计报告和CSV；明确原文日期、对象、类型、静态规则预期及实际线上召回未观察状态。
- 对照当前代码，重写README、工程说明和简历项目文字，统一模型已接入、搜索已配置、细分偏好已实现和首轮评估的实际边界。
- 更新收尾盘点，不新增生产来源、放宽时间窗口或人工填充线上库存。

## 问题与处理

1. 搜索页面的相对发布时间可能误导：以文章日期与公司公告落款为依据；赛事将在10月举行不意味着报道在10月发表。
2. 有采访链接但超过30天：保留为过期对照，不拿旧采访填满新栏目。本轮未确认新采访不等于外部没有新采访。
3. 原文存在与项目召回混淆：分别记录出版社可读、供应商返回、入库、个人展示；不给手工找到的样例标“线上通过”。
4. 历史交付文档与代码状态冲突：当前事实放在README/工程说明，历史变更保留在阶段复盘，不用旧“未接模型”状态描述当前项目。
5. 浏览器读取30秒超时：无法读取当前用户列表，已请求一次近期搜索结果截图；不要求用户提供Token，也不伪造账号内验收。

## 验收边界

本轮完成原文人工核查与文档静态链接检查，未执行功能测试、付费搜索或真实模型评估。样例是定向小样本，不用于报告全面召回率或推荐P@5。信息供给验收仍缺实际搜索记录；交付仍缺最终演示、独立问答Eval与运维记录。
