# 首轮用户反馈迭代

日期：2026-10-02。项目所有者转述了一位朋友的体验意见；这是实际用户反馈记录，不是完整操作验收或推荐质量评估。

## 收到的四个问题

1. 用户只能选择创建者预设对象，没有添加自己关注内容的入口。
2. 资讯只有标题与链接，希望不点原文就能先看概况。
3. 希望加入有区别、有用途的功能。
4. 页面视觉和文案有明显 AI 模板感。

## 本次实现

- 新增个人 Topic 与 Reading 表，通过追加 Alembic 迁移保留原有账号和反馈。用户最多添加20个自定义关注，每个包含1–5个关键词；新增后自动关注，可取消或重新关注。
- 标题、摘要、来源名称和对象标识使用字面关键词匹配。检索候选、反馈授权、阅读标记和取证工具共用用户范围逻辑，自定义关注归用户本人。
- 卡片直接展示来源摘要、原文概况或标题概况。根据实际官方原文补充18条股票/电竞中文概况；CS2两页未获得可读正文，保留标题概况与缺失说明。没有把标题猜测伪装成正文摘要，没有调用付费模型。
- 未读筛选与显式标为已读；记录存数据库，刷新或换设备仍保留。新增“先读三条”：显示按现有排序选出的三条未读，读完后自动补下一条，提供小批次阅读流程。
- 页面改为浅色、中文、紧凑的信息阅读台；移除大幅营销语、英文编号、炫光渐变；将关注管理收起，突出概况、日期和原文入口，手机显示关注下拉选择。

## 实际问题与处理

原授权依赖固定 watch_id，直接允许自定义 ID 会破坏隔离。新增共享匹配策略，只有用户自己的启用 Topic 能扩展候选；更新反馈及取证工具遵循相同范围。SQL关键词转义 %、_ 和反斜杠，避免把输入作为通配规则。

手动链接原来摘要为空。重新读取官方公告和Riot文章，用短概况保存重要数字、事件和日期；导入器只补已有空摘要，不覆盖后续编辑。财务金额注明约数，增持计划明确未等于完成，历史活动注明已结束。

“添加主题”不等于“自动接入数据源”。当前只匹配已有来源库，新的股票、战队若无匹配就显示覆盖缺口。完整的新来源接入仍需适配器及来源准入；这是第一条反馈尚未全部解决的部分。
