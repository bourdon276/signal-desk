# 阶段复盘 08：从关键词过滤改为对象关注

日期：2026-10-02。目标是处理首轮试用反馈：新增股票代码应对应股票信息；电竞关注应面向战队，不能把游戏厂商公告当成战队消息。

## 做了什么

- 前端关注创建收敛为两类：六位 A 股证券代码、CS2 战队名称。隐藏通用关键词订阅入口；存量关键词主题保留向后兼容。
- 股票对象继续使用精确 `stock:代码` 标识，并连接巨潮公告适配器。当前服务缺少 CNINFO Token 与展示许可开关，所以新股票代码可保存，但不会谎称已自动收到公告。
- 新增 PandaScore CS2 Fixtures 适配器。输入“绿龙”规范映射至 Team Spirit，服务端按订阅对象筛选赛程、进行状态和比分。赛事状态变化时更新原比赛卡片，不重复新增。
- PandaScore 私密 Token 仅通过 bearer header 发送；请求数量固定为每小时最多三次，最大响应体、超时、禁止重定向和固定主机白名单沿用来源安全边界。
- Steam News 不再由小时任务同步，原有记录保留并在来源列表标为低优先级历史收录。
- 添加战队来源私密配置说明、来源矩阵状态、覆盖提示和本阶段复盘。
- 找到 Team Spirit 官方 Telegram 频道作为真实战队新闻候选，但没有验证可用于服务端自动读取/展示的公开接口，因此仅保留人工访问链接，不抓频道页面。

## 遇到的问题和处理

1. **关注对象存在，但源并未连接。** 股票代码被保存在自定义 Topic，而真实采集依赖另行授权的 CNINFO Token。状态页应把“已保存关注”和“自动更新已启用”分开表达，并展示需要的服务端配置。
2. **游戏资讯不等于战队资讯。** Valve 新闻是游戏公告，和“关注绿龙”目标不匹配。改用 PandaScore 可用的 CS2 fixtures 作为第一种战队级数据，同时明确其不覆盖战队官方文章。
3. **原始数据会随赛事状态改变。** 若比赛 URL 不变而比分/状态变化，只靠去重插入会保留旧标题。同步时按唯一 URL 更新状态卡片和比分。
4. **私人 Token 容易误进浏览器或日志。** Token 放 Render 环境，通过 bearer header 调用固定的官方 API 主机；错误持久化只记录异常类型。
5. **不同数据平台权限不可混为一谈。** PandaScore 官方定价列出免费 fixtures 与每小时请求额度；这是其比赛数据，不意味着可以采集/再分发其他网站的战队新闻。
6. **免费套餐不等于公开演示已取得展示权。** PandaScore 现行服务条款对 Customer 身份和网站展示用途有约束。适配器保持 Token 可选；公开演示账号持有人需自行阅读条款并确认适用范围后才配置。

## Eval 与验证范围

- 继续使用既有的用户范围查询和 `candidate_filter`；实体标识采取精确匹配，避免“Spirit”任意出现在文本里就关联战队。
- 本阶段计划执行 Ruff 静态检查和 TypeScript/Vite 构建，不新增功能测试。PandaScore Token 尚未配置时无法完成真实 API schema、比赛状态更新与公网同步验收；应在完成私密配置后记录首条成功运行 ID 和真实入库数量。
- 股票来源仍要在获得 CNINFO 凭据与适用展示许可后，验证用户新增代码能触发实际数据入库。

## 仍未解决

- 需要维护者在 Render Environment 私密配置 `PANDASCORE_TOKEN`，以及确认 CNINFO 的真实 API 权限与展示许可。
- PandaScore fixtures 只覆盖匹配到的 CS2 比赛赛程与结果，不是战队新闻、转会、采访或实时直播。
- 当前每种赛事状态最多读取 100 条；免费服务休眠也会造成轮询间隔拉长。
- 通用关键词 Topic 仍为旧记录的兼容能力，但不再作为新增关注选项。
