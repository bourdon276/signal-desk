# 复盘34：用真实Eval发现批量工具与证据质量问题

日期：2026-10-09。

## 做了什么

确认事件合并上线，实际通过Enter执行采访、股票、黄金、比赛4类问题，读取回答与可见运行轨迹，人工打开美联储3条原文核对标题、文件与日期。结果保留通过、失败、未知，见真实阶段报告。

## 遇到的问题

采访合并成功，但输出内部编号、误称RSS为搜索索引；股票首轮在同批搜索两次，下一批超工具预算，摘要回退；搜索库有证券时报通用页面标题和HLTV评论摘录；比赛把未来赛程窗口终点说成过去7天截止日。HTTP成功不等于任务成功，预算预留也不等于真实供应商账单。

## 怎么解决

对同一批已有候选的重复搜索返回工具提示，不执行或计工具次数，给后续取证留额度；保持6次执行上限，跨轮错误调用与超大批次仍拒绝。每轮给剩余额度，轨迹增requested_tool_batches/skipped_tools，下次能解释模型拟调用与实际执行之差。

补当前北京时间和来源模式说明，要求不输出实现字段，区分过去赛果与未来待赛；这些提示不是效果保证，必须复测。证券时报明确通用页标题加入质量过滤，保留原数据与个人反馈。没有用通用页摘要去猜文章标题或伪造URL。

## 验收

离线合成回归31/31，其中新增同批搜索不占取证额度及通用页标题过滤2项，真实模型调用0；Ruff、前端构建通过。真实效果未复测，HLTV评论噪声未解决；浏览器控制超时与应用模型超时分别记录。整体10–20例评估仍未完成。

## 可以和面试官讨论

Prompt、工具Schema、服务端状态约束分别能保证什么；同批/跨轮调用的边界、预算失败保守记账；候选条数为何不等于信息覆盖，转载与索引页为什么影响总结。用失败驱动改进，不把模拟回归当模型准确率。
