# 小项目复盘：阅读操作提速与每日采集

## 做了什么

- 已读、兴趣反馈先更新本地界面再后台保存；只锁定当前消息，不阻塞其他消息的选择按钮。保存失败恢复该消息与计数，保留阅读位置。
- 去掉每次已读后的全量阅读台请求；连续兴趣反馈合并一次后台列表校准，并通过账号/刷新版本避免旧响应覆盖新页面。
- 去掉「新闻和比赛」合并选项，保留新闻与比赛。
- 新增批量选择和一键已读，范围为当前已加载列表，最多100条。服务端验证每条资讯属于当前账号关注后，在单一事务内冲突忽略地写入已读记录。
- 采集改为至多两来源并发，来源与轮次加锁；新增单轮命令和专用密钥的外部调度接口。
- 增加每日三次 GitHub Actions 任务，解决睡眠服务无法在登录前运行采集的问题；显示实际采集完成时间与今天发布数。
- 搜索任务跳过有效缓存，按最早到期处理，避免前十个缓存任务长期挤占后面关注的位置。
- Docker 启动不再重复导入演示链接。

## 遇到的问题及解决

1. 一次点击等待全量 `/desk` 和多项状态查询，还全局禁用按钮。改为按消息保存、即时更新，已读不再请求阅读台；反馈采用延后合并校准。
2. 乐观更新可能保存失败或跨账号响应回流。失败只恢复此次变更，账号切换废弃旧响应；待保存消息禁止重复提交。
3. 免费实例休眠导致网页内定时线程也停止。增加独立外部定时触发，但任意时刻的首访休眠延迟仍需常驻部署解决。
4. 固定前十个搜索计划占槽造成饥饿。有效缓存不占槽，未搜/过期最久的对象优先，日/月额度保持原值。

## 检查与边界

前端 TypeScript/Vite 构建、修改文件 Ruff、diff 格式检查通过。未增加或运行自动化测试。用户真实账号的偏好与批量已读不进行代操作。

Render 定时密钥已由维护者填写。GitHub 首次手动触发成功，响应显示启动采集轮次正在执行；产品页面随后显示今天采集完成时间22:22。已确认新界面包含两个栏目和批量按钮；未代用户点击已读/兴趣操作。当前列表当日新闻0条，不能视为覆盖达标，后续自动搜索改为24小时优先、手动补搜保留30天，并展示额度耗尽和待采集数。定时任务不能保证网站当天有报道、索引全面或每天每个账号都有新消息。
