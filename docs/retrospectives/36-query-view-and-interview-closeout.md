# 小项目续作36：服务端栏目约束与收尾材料

## 做了什么

将问题中的新闻/比赛/两者栏目作为服务端工具上下文。模型仍可选对象、检索数量和取证，但search_items不能通过错误view参数突破问题类别；既有采访/转会过滤继续生效。普通确定性检索与模型检索共用这一边界。

统一确定性回答中的发布日期为北京时间，解决9月28日公告在卡片写9月28日、来源列表写9月27日的时区差异。媒体当地发布日期仍需在事实评阅时单独核对。

准备下一批12项验收矩阵、更新面试材料及盘点。修复复测与新问题分开，未执行项保持待完成。

## 问题与解决

真实比赛问答虽返回比赛证据，但模型曾选择view=all；仅靠系统提示不能保证之后不混入采访。将栏目放到SearchItems服务端上下文，覆盖模型参数，而不放宽用户身份、轮数、日期或引用限制。

今日付费验收受限：每用户UTC自然日最多10次模型预算预留。查看当前时间仍处在同一UTC日；未尝试重置计数、提高额度或换账号绕过限制。下一轮应在预算可用时执行；北京时间08:00为当前实现的每日切换点，月额度不会随日切换清空。

## 检查与局限

新增新闻/比赛/混合栏目3个错参检查、北京时间跨日1个检查，累计36/36离线合成回归通过；真实API调用0，Ruff通过。新栏目约束和日期展示的线上确认待发布；模型最终JSON模式、比赛未来日期措辞仍受限未复测。

服务端类别来自中文关键词规则，复杂否定/语义可能判错。当前精确问题集合不能代表任意自然语言理解。跨源分组为已核实映射/同日同标题规则，不是通用多语言事件聚类。
