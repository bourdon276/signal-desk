# 小项目复盘：原地阅读与时间排序

## 做了什么

- 标为已读、反馈和撤销反馈后保留列表，不再先清空再加载；更新时用仍可展示的消息作为阅读位置锚点。
- 新闻列表按未读优先、发布时间从新到旧排列；已读放在后面。服务端在截取列表数量之前执行此顺序。
- 点击标题或“在阅讯阅读”打开站内阅读面板，展示收录摘录、来源和日期；面板内明确区分摘录与全文，再提供外部原文入口。
- 面板内标为已读保持面板打开；可用关闭按钮或 Escape 返回列表。

## 遇到的问题与解决

1. 通用刷新会先移除卡片，页面高度瞬间缩短，滚动位置改变。常规操作改为保留列表，并在更新后恢复相邻卡片的位置。
2. 原先按兴趣分数排序，已读资讯也可能在顶部。为阅读列表增加独立时间顺序；Agent 工具检索仍使用兴趣评分，反馈继续影响定向采集。
3. 当前来源多为摘要或索引，不能承诺站内展示完整原文。阅读面板明确标注摘录范围；全文通过用户主动点击来源链接查看。

## 检查与边界

- 前端 TypeScript 与 Vite 构建通过；修改的 Python 文件 Ruff 检查通过。
- 未增加或运行自动化测试。
- 删除或隐藏最后一条消息时，浏览器仍可能因页面内容缩短而调整滚动范围；阅读面板可保持当前内容。
- 列表候选仍受既有 500 条候选和最多 100 条展示上限约束。
