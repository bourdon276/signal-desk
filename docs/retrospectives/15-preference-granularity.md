# 小项目复盘 15：细化偏好记忆

日期：2026-10-08。状态：代码与前端构建完成，未部署、未完成新规则的独立效果评估。

## 做了什么

- 卡片显示规则识别的内容类型：版本更新、比赛赛程与结果、阵容与转会、采访、财报与业绩、公司治理公告、其他股票公告、战队新闻、其他资讯。
- “少看这类”展开三个选择：同一关注对象下的同类内容、同一来源、只隐藏当前条。无法分类时不提供同类偏好学习。
- “感兴趣”对已分类内容记录同类偏好；无法分类时只给当前条加分。最近反馈显示作用范围，撤销后从有效事件重算。
- 基于已有 `feedback_events.reason` 存储原因，无需新增表。内容/来源偏好按用户和关注对象隔离，每个维度累计权重限制在 -3 到 3；两个细分维度叠加后仍裁剪至该范围，每点对应 15 分。旧反馈保留原有对象权重，不自动改写历史记录。
- API 拒绝未知原因；服务端继续检查当前账号关注范围。浏览器不能指定目标用户或直接写偏好分数。
- 来源面板在本轮新闻匹配数为 0 时明确提示覆盖不足。

## 遇到的问题、如何解决

旧评估发现整个股票主题升权，导致不喜欢的董事会公告仍在第一。改为“关注对象 × 内容类型/来源”，减少跨类型污染。分类只使用标题与来源规则，不新增模型调用和费用；规则可能误判，页面显示分类，用户可选仅隐藏并撤销。

旧客户端没有原因字段时仍使用历史行为，避免破坏兼容。未知内容不扩大兴趣学习。历史反馈可以继续影响整个关注对象，用户须撤销相应旧反馈才能消除这部分影响。

## 战队新闻来源核查

核查使用本机代理的只读请求，不能证明 Render 网络可用性：

| 候选 | 结果 | 本轮处理 |
| --- | --- | --- |
| Esports Insider Counter-Strike RSS | HTTP 200，10 篇 | 保留现有适配器 |
| Esports Insider 战队搜索 feed | HTTP 404，即使响应能解析出条目也不视为成功 | 不接入 |
| Dexerto CS2 feed | HTTP 301 | 未确认可用，不接入 |
| Dot Esports feed | HTTP 403 | 不接入、不绕过拦截 |
| HLTV news RSS | HTTP 200，10 篇，包含 Spirit 标题 | 作为候选保留，公开展示许可未确认，不自动启用 |

核对 [HLTV 条款第 2.2 节](https://www.hltv.org/terms)时看到其对数据挖掘、网页抓取等用途的限制；公开 RSS 地址并不能单独证明本项目公开聚合展示已获许可。[官方 RSS](https://www.hltv.org/rss/news) 可读，但本轮没有据此宣称已补全绿龙新闻覆盖。
