# 复盘33：区分来源记录与采访事件

日期：2026-10-09。

## 做了什么

核查完美世界304545公开详情中的来源说明：正文明确写“接受Dust2.br的采访”，内容与Dust2 Brasil 78712原文对应。把这对URL列为人工核实的同事件记录，保留各自标题、日期、链接和阅读记录。列表同事件折叠为一张卡，展开可看其他来源；原始数据保留。

## 遇到了什么问题

原有event_key仅为URL哈希，转载URL不同就成为两个事件；工具回答会把两个来源说成两则采访。跨语言标题差异大，仅凭选手名或日期合并容易误伤不同采访。历史用户反馈已存在，改数据表可能影响撤销或旧链接。

## 怎么解决

新增只读event_identity，计算展示与工具使用的有效事件标识，不修改数据库既有event_key，不需要迁移。明确区分：这对已人工核实的跨语言转载、同对象同UTC日期且归一化长标题完全一致的保守分组、原有事件标识。短标题、未知日期、不同对象及不同日期不按标题合并。

列表先执行用户范围、日期、类型、质量、个人反馈筛选，再分组；不将隐藏内容或其他账号来源放入展开链接。组内若有未读，选择未读代表；标为已读和少看仍按单条记录保存，重复反馈按有效事件隐藏，可撤销。工具检索保留各来源记录，get_evidence附事件标识；模型要求合并叙述，服务端增加事件组数提示及trace.event_count，原文引用仍独立可查。

## 验收与限制

离线合成回归29/29通过，新增5项验证已核实转载对、对象/日期边界、未读代表与链接、列表合并而工具保留来源、重复反馈与账号隔离；真实模型调用0。前端构建与Ruff通过。生产分组与新问答尚待部署后验收，没有新增准确率结论。

这对映射来自人工核查，不是自动发现的跨语言关系；新转载仍可能漏掉。完全一致长标题也是启发式，界面标为“同题内容”，不能保证完全无误。同UTC日规则可能漏掉跨午夜转载；500条候选范围及用户筛选可能使其他来源暂不可见。未做向量/模型语义聚类，未增加模型调用或API费用。

## 后续验收

同一账号打开绿龙新闻：若两条都未被反馈隐藏，应显示一张卡、两个来源链接；标读后下一条未读可成为代表。询问近7天采访并导出记录，核对event_count=1、两条引用及合并叙述。若只返回一个来源，不能要求两条引用；不为增加条数恢复用户已隐藏内容。
