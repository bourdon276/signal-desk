# 复盘 20：对象筛选顺序与空列表诊断

## 问题

绿龙栏目显示零条消息，但来源统计有近期新闻；“未读27”来自所有关注对象。代码确认旧流程先返回全局前100条，再由前端按对象筛选，目标新闻可能在筛选之前就被全局截断。不能据此断言用户的两条新闻一定因此消失，个人反馈也可能隐藏候选。

## 修改

- `/api/feed` 增加 `watch_id`，只允许当前用户已启用的关注；未关注 ID 返回空列表，不能扩大查询范围。
- 排序器先按关注对象、内容栏目和时间筛选，再进行500条候选截断、反馈处理及返回数量截断。保持原偏好学习规则和历史评估默认调用方式。
- 前端切换对象会重新请求服务端，不再只筛全局前100条。未读数量和选中对象数量使用当前服务端范围；移除未查询对象的误导性零值。
- 返回当前范围的候选数、被没兴趣隐藏数、被重复反馈隐藏数、可展示数、未读数和截断信息；重叠隐藏归入没兴趣计数，避免重复累计。
- 返回最多20条实际导致当前候选隐藏的本人反馈及对应标题；页面直接提供逐条撤销入口，不自动删除用户反馈。避免“最近反馈仅5条”导致旧隐藏原因无法撤销。
- 切换栏目、对象或刷新时清空旧诊断并显示加载状态；已选栏目重复点击不再清空列表后停留在空状态。
- 搜索期间禁用对象和栏目切换，避免旧对象的异步结果覆盖新对象列表。

## 检查和真实验收

Ruff、格式检查及TypeScript/Vite生产构建通过；未运行功能测试，尚未读取用户登录态，因此未宣称个人新闻内容已恢复。

推送后由Render自动部署。上线后可直接查看“当前关注·当前栏目”的候选/隐藏/可展示数；若由反馈隐藏，对应撤销入口会显示具体标题。如果候选为零，继续检查搜索对象匹配与收录范围；不重新添加旧赛果。
