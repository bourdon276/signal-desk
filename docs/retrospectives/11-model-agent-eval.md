# 复盘 11：模型工具循环与 Eval

日期：2026-10-06。状态：本地实现完成，真实模型尚未配置；人工标签尚未填写。

## 做了什么

- 用 nanobot ToolRegistry 接入模型自主选择的检索/证据循环，最多 3 轮、6 次工具；服务端控制身份和引用，失败回退现有查询。
- 在 PostgreSQL/SQLite 增加预算表，原子预留月/日额度并持久化，配置 token 价格计算估算费用；日志记录模型和工具耗时，页面能查看本人运行轨迹。
- 页面明确提供可选模型开关、数据发送说明与模型/无证据/回退模式。
- 新增隔离的脚本模拟模型回归 Eval，18/18 场景通过；涵盖越权、伪造引用、预算、反馈及 API 回退。不产生实际模型费用，不是 LLM 效果指标。
- 已从本地已有资讯导出 65 条真实文章链接、130 个空白判断。保留人工标注；修复 P@5 先排除未标注候选造成的偏差及新战队标记导出报错。

## 遇到的问题与解决

仅靠提示词限制身份或链接不可取：身份固定在工具实例中，引用从服务端已取证据重建。请求并发会让内存预算失效：改为数据库条件更新，预留成功才调用模型，异常计费不明时保留额度。

此前只有确定性回答，接入框架不代表模型在决策：现在消息循环实际接收模型 tool_calls 并返回 tool results，再让模型继续。供应商密钥与价格尚缺，因此不能把代码完成说成真实模型已验证。

旧 P@5 脚本会先过滤未标注项再排名，容易造成虚高：改为固定前五，未全标注则输出 N/A；不以自动标签填补缺口。
