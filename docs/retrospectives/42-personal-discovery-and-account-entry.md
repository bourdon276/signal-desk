# 42：个人采集偏好、对象身份与账号入口

## 做了什么

- 登录/注册切换清空邮箱、密码和邀请码；退出清空个人关注、问答与偏好状态。注册表单使用新密码语义并关闭邮箱自动填充提示。
- `/api/desk` 一次返回个人首屏数据，来源与覆盖统计随后加载；注册不等待采集。不降低密码哈希强度。
- 管理关注仅列当前账号的自定义对象及已订阅内置对象，移除创建者预设股票的公共候选列表。伦敦金通过明确的添加按钮加入。
- 指数使用独立键 `index:sh:000001`，股票 `stock:000001` 表示平安银行；可将误建的个人000001股票关注改为上证指数。
- 搜索最多12个候选，扩展Dust2、完美世界电竞、5E允许来源；股票近期查询不再同时堆叠公司/公告/财报关键词。供应商没有日期的结果先返回，再由服务端严格检查最近30天。
- 东方财富批准文章路径可恢复估计日期；最多补读3篇，单篇最多4秒，仅提取标题与360字符短摘录，不跟随重定向。个人页面支持粘贴股票/指数文章链接导入。
- 本人有效的内容类型反馈形成可撤销的采集偏好；正向采访/转会/财报反馈增加对应自动采集方向，负向采访反馈可探索转会。综合采集仍保留，不清空共享资讯库。公开对象和类别共享缓存，不向搜索服务发送账号、私人显示名称或原始反馈。
- 页面展示偏好、反馈次数、排序原因和搜索实际方向，简化管理关注的供应商配置文案。

## 遇到的问题与解决

用户提供的东方财富文章实际写上证指数，不是同为000001的平安银行。仅靠六位代码会错配，因此使用类型+市场+代码区分；相关性过滤不是全部放开。实际读取还发现正文有ContentBody但标题不是h1，增加文档title的来源后缀清理。

此前反馈只改变库存排序；现在将它用于每日有额度的采集计划，并支持手动“按我的兴趣搜索”。这并不意味着每次反馈立刻完成联网采集，仍受后台排队、搜索缓存和预算限制。来源负反馈仅降低排序；“只隐藏这一条”不学习类别偏好。

## 检查与限制

52/53项离线合成回归通过，包括账号隔离、认证、指数身份、缺日期恢复、本人采集偏好与撤销。Ruff及前端构建通过；本地浏览器确认切换注册后旧输入消失，未提交真实注册。实际公开文章读取成功，标题/短摘录匹配上证指数；没有将它误配为平安银行。

这些结果不是生产新增新闻数量或延迟改善比例。尚未测量冷启动和真实注册端到端耗时；免费实例休眠延迟无法靠表单代码消除。搜索返回数量仍由供应商索引决定，域名允许并不保证索引覆盖。生产采集和偏好闭环仍需部署后观察。不新增模型调用、不调整预算上限、不替用户清空反馈或历史数据。

补充：线上旧列表发现上证指数文章曾误归stock:000001。批准东方财富文章重新匹配指数后，纠正共享记录的对象归属，保留文章ID及阅读/反馈关联；不自动迁移其他股票资讯。新增合成回归验证保留反馈身份。

生产首轮：772b767已Live，原000001个人关注已改为上证指数；后台采集后出现3条，其中包括用户提供的10月8日文章，银行资讯未进入指数列表。仍发现部分搜索摘录夹带导航文本；批准的东方财富页面增加补读，手动导入可更新同对象短摘录而保留文章身份。指数内容增加“宏观经济/指数与市场动态”类型，用于反馈排序及采集方向。更丰富供给与耗时尚未量化。
