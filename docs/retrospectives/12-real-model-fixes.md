# 12：真实模型试用后的修复

## 做了什么

- 用户提供的通鼎互联真实记录 `885e0c43-eec2-4d8d-8400-39db4750312c`：3次模型调用、6次工具、5条证据；模型时间合计6204ms，输入4325、输出1150 tokens，按配置价格估算0.01785元。未独立核对原文或供应商账单，不作为准确率结果。
- 绿龙总结出现模型失败回退，人员变动问题正确说明库内无证据；越权问题未显示私人数据，但回复成了无新闻证据。
- 在费用预留和调用模型之前，明确拒绝明显要求获取他人私人记录的问题；底层用户隔离继续生效。这层关键词提示不是完整的越权检测系统。
- 官方DeepSeek端点显式关闭思考模式：当前适配器不回传reasoning_content，官方默认思考模式要求在后续工具轮次回传；这是兼容性修复，原失败的准确原因仍待用户运行日志确认。
- 记录每轮finish_reason；回答被截断时回退并说明原因。允许完整JSON代码块包裹，继续验证对象、证据ID、引用标记和URL限制。
- API赛事无原文网页也显示编号、标题和来源，补齐模型引用对照；不会生成虚假原文链接。
- 待赛不展示默认0:0；新采集记录及旧库存展示均修复。
- 查询“最近/近期”默认近7天；“近N天”1～90天；“今天/昨天”按上海日期。含赛程/待赛/即将的近期查询额外涵盖未来7天。过滤在服务端绑定，模型不能改变范围；未知日期不进入限定时间查询。缺少数据时不自动扩大为历史资料。
- 模型开关改为同行显示。

## 问题和解决方式

供应商默认行为与兼容协议细节不同：针对官方hostname设置非思考参数，不向其他供应商发送专有参数。无网页的结构化赛事也能作证据：保留来源记录引用，而不是隐去引用或编造网页。“最近”仅靠提示词无法确保过滤：改由后端限定工具候选。
