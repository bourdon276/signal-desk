# 阶段复盘 09：修复 PandaScore 赛程漏抓与“成功但无内容”

日期：2026-10-06  
状态：代码和界面已修改；尚未部署到线上，也未用生产 Token 做端到端验收。

## 做了什么

- 原来按 CS2 的 `upcoming`、`running`、`past` 三个全局列表各取第一页，再在本地匹配 Team Spirit。PandaScore 每页最多 100 条；其它队伍的赛程可能占满第一页。
- 改成先按正式队名解析 PandaScore Team ID，再把 `opponent_id` 和 `videogame_title=cs-2` 一起传给三个比赛状态接口。`Team Spirit` 解析失败时再尝试其常见展示名 `Spirit`。
- 把比赛解析结果区分为可展示和被丢弃，并记录战队解析数、收到场次、匹配场次、新增/更新数、字段丢弃原因及达到 100 条上限的列表数。
- 完整结果显示为“同步完成”；无法解析战队或某个列表达到上限时显示“部分同步”。阅讯来源状态和当前战队覆盖提示都显示本轮统计。

## 遇到的问题与解决

之前的“已同步”只表示采集调用和数据库事务未抛错；即使匹配场次和新增记录都是 0，也会被显示为成功。状态面板没有告诉用户请求量、匹配量或丢弃原因，因此无法判断是来源没返回数据，还是本地筛选漏掉了数据。

现在以战队 ID 在 API 端收窄结果，避免无关比赛挤占全站列表；同时把处理计数展示出来。若下一轮显示“收到比赛但可展示为 0”，丢弃原因能帮助继续定位字段差异；若“收到 0 场”，则说明该 API 查询本轮没有返回该队比赛。
