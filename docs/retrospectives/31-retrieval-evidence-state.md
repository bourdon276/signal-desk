# 复盘31：有检索候选却回答没有证据

日期：2026-10-09。

## 做了什么

读取用户导出的生产运行JSON，定位Q01采访问答失败；修改模型工具循环、检索类型与回退规则，增加6项离线回归，并补充可观测字段。原始日志保留本地，公开报告不包含用户订阅ID。

## 遇到了什么问题

Q01两次检索分别有5条、3条结果，却没有执行get_evidence。3轮结束后返回“没有证据”，运行还被标为success。它满足接口成功，却未完成用户任务。旧日志没有view/news_kind，无法进一步复核当时选择的栏目，不能把否定句或别名错误写成已确认根因。

## 怎么解决

1. 将候选与证据分开处理：有候选而无证据时，下一轮工具集合只保留get_evidence，并使用供应商的指定函数tool_choice；服务端同时拒绝该阶段重复搜索。
2. 保留3轮（联网4轮）、最多6次工具的边界。模型仍未取证据则产生明确失败原因，回退已入库检索，避免把漏执行当成无新闻。
3. 给search_items增加news_kind，支持采访、阵容/转会和财报；明确采访请求在服务端限制为采访，即使模型误传比赛栏目也不返回比赛。返回content_kind，日志记录view/news_kind及解析后的筛选条件。
4. 检索回退忽略明确否定的单个类别，避免“采访，不要比赛”转向比分。该有限关键词规则不能覆盖任意自然语言否定。

## 证据与限制

离线合成回归24/24通过，真实模型调用0；新增6项覆盖上述状态边界、类型与否定规则。Q01原失败约2.759秒、估算¥0.010806，仅为单次样例，不是平均成本。修复未增加模型轮数或工具上限；成功率与成本变化仍需真实复测。

生产部署与相同问题复测尚待确认。通过条件：近7天绿龙采访被取为证据，回答仅基于采访，有可核验的引用；若没有合格候选，清楚说明范围。还需核查原文支持、完整任务与两篇转载是否同一事件，不能以24/24代替真实模型效果。

## 面试可以讨论什么

Prompt要求“先检索再取证据”并不保证模型执行。用工具集合收窄和服务端状态检查，把流程约束落到代码；区分接口成功与任务成功，并用真实失败轨迹驱动回归。限制是信息召回、跨来源事件去重与长期偏好效果仍未完全验收。
