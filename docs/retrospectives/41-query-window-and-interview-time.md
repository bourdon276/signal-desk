# 41：查询窗口与采访时间措辞

## 做了什么

针对10月10日真实复测的两处时间问题，服务端向模型和运行轨迹同时提供 `time_window_beijing`，保留原UTC查询边界。提示约束滚动窗口按精确起止时间描述，不重新计算自然日；采访发生日期未知时，不使用“同日采访”“当天采访”。不同来源发布日期不一致时，不使用“同日另一来源”。

## 遇到的问题

双股票回答将实际北京时间9月10日22:52开始的近30天窗口写成9月11日开始。混合新闻回答将10月9日和10月8日发布的来源称为“同日”，证据未提供采访发生日期。工具与引用正确，不意味着时间措辞正确。

## 怎么解决

由服务端完成UTC到北京时间的转换，把精确边界直接传入首轮上下文，并将发布时间和采访发生时间的限制写入系统指令。新增3项脚本回归，检查实际传给 completion 的上下文：滚动窗口起始日和时刻、UTC跨日转换、未指定边界保留null。

## 检查与限制

45/45项离线合成回归通过，真实模型调用0；Ruff通过。这能确认上下文传递和已有流程未回归，不能证明模型一定遵守日期指令。当天真实调用额度已用完，R06/R07时间措辞仍需额度恢复后复测，不重置额度或绕过限制。
