# 小项目复盘 16：搜索发现与受限工具调用

日期：2026-10-08。状态：本地实现与构建完成；供应商选择/凭据、真实搜索验收和部署待完成。

## 做了什么

新增可替换搜索供应商接口，首个适配为 Tavily basic。只从关注对象生成固定公开搜索词；模型选择一个对象及有限搜索类别，不直接提交任意用户问题或 URL。搜索结果经过域名、对象、CS2 上下文、估计日期筛选及 URL 去重，再入库参与个人排序。

页面增加单对象搜索入口和可选模型补搜开关。`search_news` 最多调用一次，返回本轮可见记录 ID，模型仍必须通过 `get_evidence` 取得证据。允许补搜时最多4次模型调用，既有检索路径保留3次；整体仍40秒。搜索 credits 与模型 token/人民币费用分开记录。

新增两张表的 Alembic 迁移，用于共享缓存、并发租约和原子额度预留。缓存默认6小时，失败5分钟；全站每日20/月600新请求，账号每日5次手动/Agent新请求，定时任务在全站额度内轮换。

## 遇到的问题、如何解决

- 用户质疑为何必须 Tavily：确认必须的是信息发现能力，供应商不是固定要求。将适配器与发现/存储/排序分离，默认关闭，不要求注册和付费。
- 固定 RSS 没有绿龙新闻：增加主动搜索入口，避免继续依靠库存排序解决信息供给问题。尚未用真实 Key 验证，所以不声称覆盖已改善。
- 搜索结果日期并非严格原始发布日期：只接受可解析的近30天估计日期，缺失即跳过，卡片和模型明确限制，不用当前抓取时间代替。
- 多人重复搜索与并发费用：缓存以公开实体共享，通过数据库条件更新领取租约、原子扣额度，失败保留预留，不自动重试。
- 搜索可能扩大权限或泄露标签：后端从当前账号关注映射规范对象，不能传任意 URL/问题；可从实体 ID 恢复名字时不用用户自定义标签，中文哈希战队 ID 暂不外发。
- 库存检索→补搜→取证→回答需要四轮：仅开启补搜时扩大一轮，并在请求前按四轮预留模型预算；不开补搜保留三轮预算。
