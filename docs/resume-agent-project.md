## 数字怎样使用

- 30篇是1位用户的历史兴趣标签，其中2篇无法判断。不是事实核验集或线上用户数。
- 留出前五明确想看1→3，另1篇未知；精确P@5为N/A，界限60%–80%。不建议在简历写“准确率提升40%”。
- 一个真实问答轨迹包含3次模型、6次工具、5条证据，估算¥0.01785。适合解释调用与预留机制，不代表平均成本。
- 当前36项离线合成回归通过，真实模型调用0；真实问答已有6种问题及多次复测，存在已记录失败，不能写为准确率。

## 已有可讲的真实调试案例

1. **采访有候选、模型却答无证据**：轨迹显示反复搜索但不取证。进入取证阶段后只暴露get_evidence，服务端不允许有候选而直接声称无证据；真实同题复测取得2条证据。
2. **2个来源不等于2次采访**：核实完美转载与Dust2原文后合并为1个事件，保留独立原文链接；范围只覆盖已核实映射和保守标题规则。
3. **stock检索成功，回答仍失败**：先修工具额度，真实复测取回3条证据；随后发现invalid_answer_json，补官方JSON模式。最新效果被日限额拦截，尚未证明修复通过。这能说明Eval是发现新失败并迭代，而非只看接口200。
4. **权限与成本边界**：实际越权问题返回policy_denial，模型/工具0调用、费用0。日限额拦截后保留证据检索，未提高预算绕过验收。

面试时说明已验证的结果、未验证的边界和下一步实验。可以讲真实上线、工具循环、反馈记忆与失败调试；不能把规则记忆说成模型训练，也不能把一次兴趣回放说成泛化效果。
