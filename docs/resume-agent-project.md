## 面试可以聊什么

| 主题 | 已实现内容与取舍 |
|---|---|
| 为什么不只装 Skill | Skill 能辅助单人查消息；产品负责多用户状态、定时采集、反馈历史与浏览入口。这些能力需要持续运行的服务。 |
| 通用 Agent 做不好的部分 | 绿龙映射 Team Spirit，而供应商展示名为 Spirit；先解析战队 ID，再请求。全站前 100 条和 HTTP 200 都不代表覆盖目标战队。 |
| 上下文工程 | 按用户关注过滤，检索最多 5 条元数据，再取得每条最多 500 字摘要。当前没有 LLM 上下文窗口实验。 |
| 记忆 | 反馈事件重放、主题权重、已读记录与撤销；是规则偏好记忆，不是向量记忆或模型训练。 |
| 工具和安全 | 后端绑定用户身份，共享权限函数用于列表和证据工具；只开放只读工具，API Token 留在服务端，固定来源与链接白名单。 |
| 可靠性 | 超时、响应大小限制、幂等入库、失败保留旧数据；尚无完整退避重试、跨进程任务锁或全天 SLA，免费服务休眠会暂停轮询。 |
| 成本 | 当前无模型调用，模型成本为零。¥200/月是预算，不能说成已测的总成本。 |
| 观测调试 | run_id、工具耗时、返回/匹配/入库/丢弃数量。404 暴露了上一轮验收只检查入库、没有检查引用页面的不足。 |
| Eval | 已有人工标注模板与 P@5 基线报告脚本；真实标注及效果报告尚未完成，不能编造指标。 |

## 为 Agent 开发岗最值得补的两项

1. 受限模型工具循环：最多 3 轮、6 次工具调用，后端固定用户身份；引用、无证据拒答、超时回退、token 与费用记录。模型负责选择工具与组织回答，采集仍用确定性适配器。
2. 小规模真实 Eval：至少 30 条人工标签，对比时间排序与反馈排序的 P@5；问答案例包含别名、无证据、跨用户访问、来源失败和无效引用。记录失败案例与样本偏差。

现在可以投递，不必等完美；补齐这两项后再把简历定位升级为“受限工具调用 Agent”，面试更有说服力。
