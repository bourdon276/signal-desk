# 搜索发现新闻：配置与边界

当前状态：本地代码已接入，默认关闭；尚未配置 Key、进行真实搜索验收或部署本版本。Tavily 是首个适配器，可替换，不要求现在注册或付费。

## 为什么增加搜索层

固定 RSS 窗口里没有目标战队时，继续调整模型和推荐权重无法补齐供给。现在由搜索服务发现链接，再做对象匹配、日期筛选、去重和个人排序。DeepSeek 继续负责选择工具和总结，不需要更换现有模型供应商。

```text
用户关注股票/CS2战队 → 固定公开对象搜索词 → SearchProvider
                                              ↓
允许名单域名 + 实体/游戏核对 + 近30天估计日期 → 去重入库
                                              ↓
                       个人偏好排序 ← 内容类型/来源反馈
                                              ↓
                    search_items / search_news → get_evidence → DeepSeek
```

不保证全网覆盖；当前只对股票与 CS2 战队启用发现，不包含黄金、LoL、Valorant。

## 可替换的供应商

`src/information_agent/search_provider.py` 定义 `SearchProvider`：输入公开对象搜索词和允许名单域名，输出标题、URL、短摘录、发布时间估计。当前实现为 Tavily basic，固定单次 1 credit 的配置。要替换供应商，新增实现并调整 `provider()` 与 `configured()`；发现流程、缓存、记忆和工具不用重写。新适配器须重新核对价格，并更新额度预留规则，不能直接沿用 1-credit 假设。

RSS、现有 PandaScore 与股票接口仍可独立使用，缺少搜索 Key 不影响已收录内容。

## 若选择 Tavily

官方 [Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search) 支持日期、域名和搜索深度设置；[价格说明](https://docs.tavily.com/documentation/api-credits)在 2026-10-08 标明每月 1,000 免费 credits，basic 每次 1 credit，无需绑卡。账户套餐与剩余额度以自己的 Dashboard 为准，项目的计数不能代替供应商账单；无需为本项目开启按量付费。

在 Render 服务的 Environment 添加：

```dotenv
SEARCH_ENABLED=true
TAVILY_API_KEY=在Render中私下填写
SEARCH_DAY_CREDIT_LIMIT=20
SEARCH_MONTH_CREDIT_LIMIT=600
SEARCH_USER_DAY_LIMIT=5
SEARCH_CACHE_HOURS=6
```

密钥只存服务器环境，不放 Git、前端或聊天。现有 DeepSeek 模型配置保持有效。只有上述开关与 Key 同时存在才会发送搜索请求。要暂停搜索，把 `SEARCH_ENABLED` 改回 `false`。

## 两个入口

1. 信息流选中一个股票/CS2 战队，点击“搜索这个关注的新消息”，无需调用模型。匹配结果入库后重新加载个人信息流，返回缓存/预算/失败/零匹配状态。
2. 勾选模型工具问答，再勾选“允许库存不足时联网补搜一次”。模型可调用 `search_news(watch_id, focus)`，随后仍须 `get_evidence` 才能引用。每轮问答最多补搜一次、6 次工具、最多 4 次模型请求；不开补搜仍最多 3 次模型请求。整个问答仍限 40 秒。

后台沿用每小时调度；搜索缓存命中不请求供应商。Render 休眠时不持续采集。新增对象加入搜索队列，不承诺立即有结果。

本地部署先运行 `uv run alembic upgrade head`，增加 `search_cache` 与 `search_budgets` 两表。独立采集入口为 `uv run python -m information_agent.web_search`，只读取当前已有订阅。生产容器启动脚本会执行 Alembic 升级。

## 预算、共享缓存与可靠性

- 按公开实体、搜索类别、域名名单及供应商版本缓存；不按用户问题原文缓存。默认缓存 6 小时，失败缓存 5 分钟。
- 同一实体可跨用户复用公开资讯，但每次返回仍按当前账号关注、反馈和时间范围筛选；不共享用户反馈或关注列表。
- 数据库原子预留月/日 credits；手动与 Agent 请求另有每用户每日 5 次新请求上限，缓存命中不扣额度。预算日/月按上海时间划分。
- 并发同一搜索使用数据库租约，已在途时返回 busy；无自动重试。超时和不确定失败保留 1 credit 预留，避免把失败当免费请求。
- 定时采集每轮最多 10 个去重实体，按日期哈希轮换优先次序，在全站日额度内运行。订阅过多时部分实体不能及时采集，页面不得声称全部覆盖。
- 网络超时上限 15 秒，响应不超过 128KB，不跟随重定向；只调用固定搜索 API，不由模型指定抓取目标。网页结果不触发服务器直接抓取。
- 运行记录保存耗时、缓存命中、credits、返回/匹配/新增数量和丢弃原因，不保存完整问题、搜索正文、请求头或密钥。搜索 credits 与模型人民币费用分开显示。

## 证据与已知限制

- 结果只接受允许名单域名、HTTPS 链接和可解析的近30天日期。发布时间是搜索服务估计，可能为页面更新时间；缺失/未来/窗口外日期丢弃，不拿抓取时间冒充发布时间。
- 股票需匹配六位代码或本项目登记的规范公司全名。未知股票只用代码，可能漏掉未包含代码的报道。
- 战队从规范实体 ID 恢复队名；搜索内容还须匹配战队/已登记别名与 CS2 上下文。不能恢复规范公开名字的中文哈希 ID 暂不支持搜索，避免将用户自定义标签外发。
- 只保存短搜索摘录、标题和链接，标记“未核验全文”“日期待核验”；没有逐条访问原文验证 HTTP 状态。搜索索引可能陈旧、链接可能失效。
- URL 规范化去掉片段和常见追踪参数；不保证同事件跨网站去重。现有 URL 唯一约束使多队文章只保存到首个对象，不能计作其他对象的覆盖。
- 搜索摘要和页面内容均为不可信数据，不能授予工具权限或替代后端的用户范围检查。引用仍由服务器从已取得证据重建，模型不能编造 URL。
