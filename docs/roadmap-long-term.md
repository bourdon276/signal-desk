## 1. 最终目标

做一个外部用户可以通过 HTTPS 访问、能持续使用的资讯产品。它围绕用户关注的股票、伦敦金和电竞项目收集消息，合并重复事件，给出带原文出处的摘要，并根据“感兴趣 / 没兴趣 / 重复 / 来源不喜欢”等反馈调整后续推荐。至少完成一次为期 14 天、由真实外部用户参与的试用。

首版关注对象：

| 领域 | 首批对象 | 首批来源与边界 |
| --- | --- | --- |
| A 股 | 通鼎互联（002491.SZ）、辉煌科技（002296.SZ） | 交易所和巨潮资讯公告优先；同花顺、东方财富等资讯在确认接入权限后补充。 |
| 黄金 | 伦敦金相关资讯 | 利率、美元、央行与黄金市场事件；首版不做实时金价、交易信号或买卖建议。 |
| 电竞 | 英雄联盟、CS2、无畏契约 | Riot 官方新闻与完美世界电竞是候选来源，接入权限仍需核实。虎扑自动获取受现行协议限制，未获书面许可前不接入。社区讨论与官方消息分别标记。 |

每周 AI 简报和私有阅读源保留为下一阶段能力，不纳入首版验收。首版支持试用者自行设置关注对象，不能把开发者的自选股和游戏偏好共享给所有人。

### 为什么需要这个项目

通用 Agent 可以按要求总结一批链接，但持续运行时缺少稳定的来源适配、证券代码与游戏实体识别、跨平台事件去重、用户级偏好状态、推送控制及来源核验。本项目把这些能力做成可维护的数据和工具流程；nanobot 负责受控的 Agent 交互、工具接入和运行调度。对比基线是“按时间倒序的关键词资讯列表”，而不是只展示模型生成的摘要。

## 2. 总体架构与技术选择

```text
来源适配器 → 原文与元数据入库 → 实体识别、事件聚合、事实提取
                                          ↓
用户关注与反馈 → 可解释排序 → 摘要/问答 → Web 信息流与定时简报
                                          ↓
                               运行轨迹、质量与成本指标
```

- **Agent 层：**锁定一个 nanobot 版本；优先通过 Python SDK、自定义工具或插件扩展，不在开始时修改其核心循环。若扩展点不足，单独记录必要的上游改动、原因和回迁办法。nanobot 支持工具、MCP、定时任务、SDK 与独立实例，见[架构](https://github.com/HKUDS/nanobot/blob/main/docs/architecture.md)、[Python SDK](https://github.com/HKUDS/nanobot/blob/main/docs/python-sdk.md)和[多实例说明](https://github.com/HKUDS/nanobot/blob/main/docs/multiple-instances.md)。
- **采集与 API：**Python 3.11+、`httpx`、页面/RSS 解析、FastAPI、Pydantic。每个来源独立适配；保留 URL、发布时间、抓取时间、来源类型和原文证据。只有在核实允许自动接入及相应用途后才启动适配器；用户提交链接只保存链接，不自动抓取受限正文。
- **数据：**本地阶段 SQLite；公开试用前迁到 PostgreSQL，使用 SQLAlchemy 与 Alembic 管理模式。表至少包括 `sources`、`items`、`story_clusters`、`users`、`watches`、`feedback_events`、`preference_profiles`、`deliveries`、`agent_runs`。向量检索仅在关键词基线不足时加入。
- **用户界面：**React + TypeScript 信息流和反馈按钮，FastAPI 提供受限 API。公开 Web 入口只暴露资讯、搜索、关注与反馈能力；nanobot 的通用 Shell/文件工具和管理 WebUI 不对试用者开放。用户身份、数据查询和写入均限定在对应 `user_id`。
- **运行与部署：**本地 Docker Compose；公开试用使用一台支持持久存储的主机、Docker Compose、HTTPS 反向代理、数据库备份和进程重启。nanobot 官方也提供 Docker 与 Render 部署路径；Render 的持久盘方案需要付费服务，实际主机在小项目 0 核算成本后确定。[部署文档](https://github.com/HKUDS/nanobot/blob/main/docs/deployment.md)

模型只处理确实需要语义理解的分类、事实提取、摘要与交互。来源抓取、代码匹配、去重、权限检查、排序硬约束和发送去重由确定性代码负责。

## 3. “做好了”的可检验定义

以下是首版目标值。小项目 0 要冻结评测方法和样本划分；如果数据源现实使阈值不适用，必须在复盘中说明并修订，不能在看到结果后暗中改口径。

| 维度 | 首版完成门槛 | 证据 |
| --- | --- | --- |
| 可访问与真实使用 | 有可从外网访问的 HTTPS 地址和试用账号；至少邀请 5 名非开发者，至少 3 人在不同的 3 天使用；连续试用 14 天 | 匿名化活跃记录、经同意的访谈摘要和线上地址 |
| 来源与时效 | 每条展示信息都有原始 URL、来源类型及发布时间或“未知”标记；在固定来源样本中，两只股票的公告捕获率 ≥95%；可观测来源的普通资讯 90% 在出现后 4 小时内入库 | 每日来源审计、采集延迟报表；无新公告日不计入分母 |
| 相关性 | 冻结评测集上，前 10 条推荐的人工相关率 `Precision@10 ≥ 0.80`，且比倒序关键词基线至少高 10 个百分点 | 分主题、分用户画像的离线结果和错误案例 |
| 事实与去重 | 推送卡片 100% 带原文链接；50 条重点股票/黄金摘要人工抽查中，无关键事实无来源支持；同事件重复推送率 ≤5% | 证据对照表、事件聚合样本 |
| 反馈有效 | 重复项点击“重复”后不再推同一事件；某游戏的负反馈不改动其他游戏或股票偏好；用户可以查看和撤销反馈 | 固定反馈案例与偏好版本记录 |
| 运行质量 | 14 天试用期可访问性 ≥99%，定时任务成功率 ≥98%；来源故障、模型失败、推送失败均能定位到一次运行 | 监控面板、带 `run_id` 的日志与故障复盘 |
| 权限与成本 | 不出现跨用户数据读取；公开接口不能调用通用执行工具；模型/API 费用低于小项目 0 冻结的试用预算上限 | 权限检查、费用报表和预算告警 |
| 文档 | 新开发者能按最终 README 在空环境启动本地演示；部署、评测、限制与数据删除步骤齐全 | 外部试读记录、README 和部署演示 |

离线评测先人工标注至少 120 条，覆盖两只股票、伦敦金和三款游戏；发布前扩至至少 240 条，另建同名实体、旧闻、转载、传闻、提示注入和来源缺失等困难样本。按时间切分训练/调参与最终评测，避免同一事件同时进入两边。小样本指标只能说明本轮试用表现，不宣称已经证明长期推荐效果。

## 4. 小项目路线

每个小项目只有通过自己的验收并写完对应复盘，才算完成。复盘使用 [`docs/retrospectives/TEMPLATE.md`](docs/retrospectives/TEMPLATE.md)，记录真实结果，不预写“已解决”的故事。

| 小项目 | 预计 | 主要交付物 | 完成条件与复盘文件 |
| --- | --- | --- | --- |
| **0. 产品范围、来源与 Eval 基线** | 4–6 天 | `docs/source_matrix.md`、用户流程、预算表、首批标注集、评测脚本说明和试用者招募名单 | 6 个关注对象都有候选来源、权限与降级策略；固定关键词/时间倒序基线；冻结上述 Eval 口径；匿名核实至少 5 位愿意试用的外部用户。`docs/retrospectives/00-scope-eval.md` |
| **1. 多源采集与持久化** | 1–2 周 | 已获准来源的股票官方公告、伦敦金资讯和电竞官方消息适配器；数据库迁移 | 重跑采集不产生重复记录；来源失败会记录并重试；每个对象至少有一条可回溯的真实内容。虎扑仅在获得书面许可后接入。`01-ingestion.md` |
| **2. 领域识别、去重与证据摘要** | 1–2 周 | 股票代码/别名与游戏、赛事、战队实体表；事件聚合；结构化摘要及“无法确认”状态 | 历史样本中实体匹配准确率 ≥95%；同事件多来源能合并；摘要事实可定位到原文，社区传闻有明确标签。`02-evidence.md` |
| **3. 用户偏好、反馈与推荐** | 1–2 周 | 用户关注表、反馈事件、可撤销偏好画像、规则排序和倒序关键词对照 | “没兴趣”的原因分别影响主题、来源或重复事件；偏好按用户与领域隔离；完成首轮离线排序对比。`03-personalization.md` |
| **4. nanobot 工具、上下文与记忆** | 1 周 | `search_items`、`get_evidence`、`explain_recommendation`、`update_watch`、`record_feedback` 等受限工具；摘要与问答流程 | 工具参数经过 Schema 校验，调用/输出长度有限；答案给出处；模型遇到缺失证据会说明未知；能复现一次完整工具轨迹。`04-agent-integration.md` |
| **5. 多用户 Web 产品** | 1 周 | 登录、个人关注、信息流、推荐理由、反馈和删除个人数据入口 | 两个试用账号的关注、反馈、搜索结果互相隔离；手机浏览器可以完成主要流程。`05-web-product.md` |
| **6. 可靠性、安全、成本与观测** | 1–2 周 | 超时/重试/幂等、来源健康指标、结构化日志与 trace、预算闸门、权限和外部内容威胁模型 | 模拟来源超时与模型失败可降级；失败可按 `run_id` 找到原因；超预算时停止非必要模型调用；关键安全边界有验证记录。`06-operations.md` |
| **7. 对外部署** | 4–6 天 | HTTPS 地址、持久卷/数据库、备份恢复、监控与回滚步骤 | 外部网络可访问；重启后数据与反馈仍在；一次备份恢复演练成功；部署步骤有人照文档复现。`07-deployment.md` |
| **8. 真实用户试用、最终 Eval 与 README** | 至少 14 天 | 邀请试用、匿名化使用数据、访谈、最终指标和错误分析、完整 README、短演示 | 达到第 3 节的用户与质量门槛；展示失败案例和改动前后对比；最终 README 经非作者试读。`08-beta-release.md` |

反馈的具体语义在小项目 3 落地：“重复”只屏蔽同一事件，“来源不喜欢”下调该来源，“主题没兴趣”下调相应对象或子主题；每次反馈都保留原始事件和作用范围。画像由事件重算、带版本号与时间衰减，允许撤销。高优先级的公司正式公告仍可展示，但可以进入摘要而不主动打扰；这条规则也必须进入 Eval。

试用者在小项目 0 招募，小项目 7 部署完成后再发邀请。招募目标同时覆盖股票与电竞兴趣，避免只用与开发者偏好完全相同的人验证推荐。试用记录只保存必要的匿名化指标；访谈引述与截图在对外展示前逐项征得同意。

### 小项目 0 的来源决策重点

- 股票公告优先从[巨潮资讯](https://www.cninfo.com.cn/)和交易所披露取得。同花顺 [iFinD 接口](https://quantapi.10jqka.com.cn/gwstatic/static/ds_web/quantapi-web/help-center/manual.html)、东方财富 [Choice 接口](https://choice.eastmoney.com/choicewebfile/UserGuide.pdf)需要相应账号或权限；没有权限时不依赖它们完成核心路径。
- 电竞候选包括 [LoL Esports](https://lolesports.com/news)、[VALORANT Esports](https://valorantesports.com/en-GB/news/)与[完美世界电竞](https://www.pwesports.cn/)官方消息，自动接入和展示规则仍需核实。[虎扑协议](https://www.hupu.com/policies/user)限制未经书面许可的自动程序获取内容，许可前不开发虎扑采集器。转载、用户帖子与官方消息分别保留来源级别。
- 伦敦金先确定可稳定获取、可引用的资讯源；资讯与报价分开设计。[LBMA Gold Price](https://www.lbma.org.uk/prices-and-data/lbma-gold-price)的基准价数据使用有单独许可要求。

## 5. 对 Agent 工程问题的回答与证据

| 必须能回答的问题 | 在项目里给出的具体回答 | 可展示证据 |
| --- | --- | --- |
| **什么叫做好了 / Eval** | 相关性、来源支持、重复率、时效、用户实际使用、运行与成本都有门槛；失败则继续迭代 | 冻结评测集、基线对比、线上 14 天记录 |
| **通用 Agent 做不好的部分** | 专用来源适配、证券/赛事实体别名、事件去重、来源层级与用户反馈排序 | 通用“搜一搜再总结”和本系统对同批问题的对照样例 |
| **上下文工程** | 每次只送相关用户偏好、少量候选摘要和可核验证据；网页正文按不可信数据处理，明确 token/工具结果上限 | 上下文构造图、一次 trace 的输入构成和 token 数 |
| **记忆系统** | 显式关注、不可变反馈事件、可重算的偏好画像、短期会话分开存；支持衰减、撤销、删除 | 数据模式、偏好变化与回滚实例 |
| **工具调用** | 只注册任务所需的只读搜索/证据工具和经身份校验的反馈工具；参数、次数、超时与返回量受限 | 工具 Schema、成功与失败调用轨迹 |
| **可靠性** | 拉取幂等，失败重试有界，来源故障降级，摘要失败不冒充成功，发送去重 | 故障注入记录、恢复与备份演练 |
| **安全** | 账号与数据隔离、密钥管理、外部页面提示注入隔离、URL/网络边界、最小权限；股票资讯不生成交易指令 | 威胁模型、权限与注入案例、公开入口清单 |
| **成本控制** | 先去重和规则筛选再调用模型；缓存同事件摘要；按来源、模型、用户计量并限制预算 | 每 100 条入库与每位活跃用户的费用报表 |
| **观测与调试** | 一条资讯从抓取到展示共用 `run_id`/`item_id`，记录耗时、模型和工具错误类别 | 指标面板与一次真实故障的定位过程 |
| **评估与迭代** | 离线标注集、难例、线上反馈、访谈和错误分类同时使用；每轮改动与基线比较 | 版本化 Eval 报告、复盘中的前后差异 |

## 7. 执行规则

1. 每阶段提交代码、配置示例、样本或报告，写明能从哪里复现结果；复盘说明做了什么、遇到的问题、原因、解决办法、未解决事项和下阶段调整。
2. 先保留一个不用模型也能运行的倒序关键词基线。增加模型能力时必须能说明其对指标的实际贡献。
3. 新来源失败时显示来源不可用与最后成功时间，不用模型补造当天消息。对财经信息保留源文与时间，不提供自动交易动作。
4. 对外试用必须经身份验证；真实用户的私密关注、阅读和反馈只在其账号下使用。对外展示效果时先匿名化并获得用户同意。
5. 小项目 8 结束时，如真实用户门槛、线上部署或关键质量门槛未达成，项目状态标为“试用中”，README 如实列出差距与下一步。
