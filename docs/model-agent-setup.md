# 受限模型工具循环

## 目前状态

代码已接入 nanobot 的两个工具，模型自主选择调用，再根据证据组织答案。尚未配置真实供应商、模型和密钥；默认关闭，不产生模型费用。脚本模拟模型的 18 个回归场景已通过，不能作为真实模型质量结果。

## Render 配置

在 `signal-desk-demo → Environment` 私密填写；密钥不要发到聊天、浏览器前端或 Git。

| 环境变量 | 填写方式 |
|---|---|
| MODEL_ENABLED | `true` |
| MODEL_API_KEY | 供应商密钥 |
| MODEL_BASE_URL | 供应商 HTTPS 基地址，通常以 `/v1` 结尾，不能含密钥/查询参数 |
| MODEL_NAME | 供应商支持 Chat Completions 工具调用的模型 ID |
| MODEL_INPUT_CNY_PER_MILLION | 每百万输入 token 的人民币价格，必须大于 0 |
| MODEL_OUTPUT_CNY_PER_MILLION | 每百万输出 token 的人民币价格，必须大于 0 |
| MODEL_MONTH_BUDGET_CNY | 默认 `50`，为 ¥200 总预算留出服务和数据预算 |
| MODEL_DAY_BUDGET_CNY | 默认 `3` |
| MODEL_REQUEST_BUDGET_CNY | 默认 `0.5` |

兼容接口使用 `POST /chat/completions`、`tools`、`tool_calls`、`max_tokens`。供应商可能存在参数差异；不是所有模型都支持这个协议。OpenAI 的部分新模型要求 Responses API，本版本未实现 Responses 适配器，不能直接配置这些模型。

保存并部署后，`/api/agent/status` 应返回 `configured=true`。登录并勾选“模型工具问答”，再发起查询。用户开启前界面说明问题、关注名和短证据发送到配置服务；默认仍是本地证据检索。

## 设计与边界

- 模型最多请求 3 轮、执行 6 次工具。第一轮查候选，后续取得证据，最后一轮不允许调用工具。允许模型自主选择调用路径，也可能因未调用证据工具而返回无证据。
- 用户身份由服务端绑定，不接受模型指定身份。证据 ID 必须来自本次用户检索；工具再核验用户范围。模型不能访问 HTTP 抓取、文件、Shell 或写入工具。
- 单请求消息体上限 16KB，单工具短证据上限 500 字，最多引用 5 条。模型响应下载上限 128KB，整体 40 秒超时，失败回退确定性检索。
- 最终回答使用证据 ID，链接和标题由后端生成；拒绝未知引用和模型生成的 URL。结构合法不代表语义正确，事实支持仍需人工 Eval。模型输出中的引用标识被替换成易读序号。
- 反馈记忆仍是可撤销事件驱动的排序规则，经检索结果影响模型上下文；不发送完整反馈历史，不构造向量记忆或假设模型自行学会用户偏好。
- 原文中的指令作为不可信数据，提示层提醒模型忽略；实际权限靠工具约束。尚不能声称已通过真实模型的提示注入评估。

## 成本与运行记录

模型请求前，在数据库按全站月、全站日、每用户日原子预留费用，用户每天最多 10 次模型请求。并发更新失败会整体回滚；重启保留预留。按输入字节上限和输出 token 上限、配置价格保守预留，不依赖内存计数。

供应商 usage 完整时按报告 token 结算估算费用；响应用量缺失、超时或流程失败时保留整笔预留，避免误认为未计费。进程中断也不会退款。价格配置必须准确，且供应商遵守输出上限；应用估算不能代替账单或供应商侧硬预算。供应商额外计费、错误价格、异常 tokenizer 均可能使估算偏离实际账单。

运行日志保存模型轮数、工具参数/结果数/耗时、token 与估算费用、失败分类，不保存完整问题、证据内容或回答。页面可查看本人记录；`GET /api/runs/{id}` 验证归属，跨用户返回 404。未实现分布式模型并发限流，后续可补。

## 真实模型验收

配置后逐一检查：关注对象别名查询、没有证据、要求读取他人记录、要求忽略系统限制、供应商失败、费用耗尽。填写每次 run_id、实际工具轨迹、引用支持、耗时和费用。确认回答事实逐条有证据、越权请求拒绝、失败时明确回退。优先完成 10 个真实模型问答案例和至少 30 条人工新闻标签，再写简历效果数据。
